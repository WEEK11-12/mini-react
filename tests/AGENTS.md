# 테스트 작업 지침

상위 [AGENTS.md](../AGENTS.md)를 먼저 적용하고, 새 테스트를 쓰기 전 [테스트 컨벤션](conventions.md)과 해당 요구사항·설계를 읽는다. 이 파일은 `tests/`에만 적용한다.

- 검증 단위의 소유권을 지킨다. 구현자가 작성한 스모크와 검증자가 작성한 독립 사례를 구분하고, 기존 성공 테스트의 기대값을 새 구현에 맞춰 약화하지 않는다.
- 기능 계약은 `renderer/`, `runtime/`, `history/`; 테스트 도구의 검출력은 `harness/`; 실제 브라우저 흐름은 `browser/`; 단계별 독립 검증은 각 대상의 `review/`; 공유 fixture·진입 도구는 `support/`에 둔다. 새 파일명과 제목은 `conventions.md`를 따른다. 과거 단계 파일명 예외는 새 파일에 복제하지 않는다.
- 테스트가 실패한 이유를 구분한다: 실제 제품 결함, 검증 코드 오류, 앱/브라우저 환경 차단, 후속 단계 미구현, 기존 baseline 실패. 실행하지 않은 테스트를 통과나 skip으로 계산하지 않는다.
- `npm run check:conventions`와 새 파일의 선택 실행을 수행하고 원본 runner의 고유 사례 수·실패 분류를 대조한다. 모든 공개 테스트 실행 명령은 사전 컨벤션 검사를 거치며, 문서상의 총계를 그대로 믿지 않는다.
- 제품 소스를 검증 중 임의 수정하지 않는다. 수정 요청에는 재현 조건·관찰값·관련 설계·범위를 명시한다. 재검토는 같은 변경의 지적 사례 및 영향 경로만 수행한다. 검토 보고서·runner·해시는 저장소 밖이나 무시되는 `reports/`에 둔다.
