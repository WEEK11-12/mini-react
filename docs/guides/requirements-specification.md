# Markdown 요구사항 명세 작성 가이드

이 가이드는 [미니 React 요구사항 명세서](../requirements.md)를 작성·리뷰할 때 사용한다. **`docs/requirements.md`가 유일한 SRS 본문**이다. 별도의 보고서나 Word 문서를 기준 원본으로 두지 않는다.

## 1. 문서와 항목의 관계

`과제 원문 → requirements.md의 범위·제약·기능 요구 → design.md의 해결 방법 → 테스트·브라우저 검증`

SRS는 프로젝트의 목적부터 미정 사항까지 담는 **전체 문서**다. 기능 요구사항은 그 안의 한 장이며, 각 독립 동작에 ID를 붙인다. ID 하나를 버튼 하나나 코드 함수 하나와 기계적으로 대응시키지 않는다.

| 적을 내용 | 문서 | 예 |
| --- | --- | --- |
| 기대 동작·완료 기준 | [requirements.md](../requirements.md) | Patch 후 변경된 내용이 실제 영역에 반영된다. |
| 해결 구조·선택 이유 | [design.md](../design.md) | 이전·다음 트리를 비교한 변경 정보를 DOM에 적용한다. |
| AI의 작업 규칙 | [AGENTS.md](../../AGENTS.md) | 미정인 이력 분기 정책을 임의로 확정하지 않는다. |

## 2. 요구사항 한 건의 형식

| 필수 항목 | 작성 기준 |
| --- | --- |
| **ID** | 문서·설계·테스트에서 가리킬 고유 번호 |
| **요구 동작** | 주체와 동작이 드러나는 한 문장 |
| **출처** | 과제 원문 Phase·팀 결정·추가 제안 중 근거 |
| **우선순위** | 필수 또는 선택·확장 후보 |
| **인수 조건** | 주어진 상황·행동·관찰 가능한 결과 |

`FR-XX`는 형식을 보여주는 예시 ID다. 실제 번호는 [요구사항 명세서](../requirements.md)의 항목과 중복되지 않게 정한다.

### 작성 예

> **ID:** FR-05
> **요구 동작:** Patch를 누르면 테스트 영역의 현재 상태를 다시 읽고 실제 영역에 변경을 반영한다.
> **출처:** 과제 원문 Phase 1
> **우선순위:** 필수
> **인수 조건:** 테스트 영역의 글자를 바꾸고 Patch를 누르면 실제 영역의 글자도 바뀐다.

인수 조건에는 **확인 가능한 결과**를 쓴다. 트리 필드, 함수명, 탐색 알고리즘처럼 해결 방법을 지정해야 할 때는 과제의 명시적 제약인지 확인하고 설계 문서에 연결한다.

## 3. 시나리오·인수 테스트·모델

| 표현 | 목적 | 이 프로젝트에서 필요한 때 |
| --- | --- | --- |
| 사용자 시나리오 | 사용자가 어떤 순서로 목표에 도달하는지 설명 | 편집 → Patch → 뒤로가기처럼 여러 요구가 이어질 때 |
| 인수 조건 | 한 요구가 충족됐는지 판단 | 모든 기능 요구사항 |
| 인수 테스트 | 입력·조작·기대 결과를 실제로 확인 | 구현 후 기능 검증 |
| 모델 | 구조·상태·전이를 간결하게 표현 | History 분기나 Hook 수명을 문장으로 설명하기 어려울 때 |

인수 테스트도 시나리오 형식으로 작성할 수 있다. 다만 **사용 흐름을 설명하는 시나리오**와 **통과 여부를 판정하는 테스트**의 목적을 구분한다. 긴 시나리오·도식은 필요할 때 별도 Markdown 파일로 분리하고 관련 요구 ID에서 연결한다.

## 4. 미정 사항과 변경

과제 원문이 정하지 않은 정책은 자연스러워 보여도 인수 조건에 몰래 넣지 않는다. [미정 사항](../requirements.md#6-미정-사항과-결정-기록)에 질문·영향받는 ID를 남기고, 팀이 결정하면 요구·설계·테스트를 함께 갱신한다.

PR 리뷰에서는 다음을 확인한다.

- [ ] 필수 기능과 선택·확장 후보가 구분되어 있다.
- [ ] 각 기능 요구에 다섯 필드가 있고, 인수 조건을 실제로 판정할 수 있다.
- [ ] 과제 원문과 팀 선택을 구분했으며, 미정 정책을 확정처럼 쓰지 않았다.
- [ ] 요구 ID가 설계 결정과 검증 계획에 연결된다.
- [ ] 링크가 열리고 이전 언어·문서 체계의 설명이 남아 있지 않다.
