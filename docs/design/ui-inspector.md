# UI와 Diff·Patch 시각화

상태: 사용자 요청으로 구현. 관련 필수 요구 FR-03·04·16을 관찰하는 선택 확장이다.

## 목적과 화면

- 두 Phase를 밝은 회색 배경·흰 카드·파란 강조색·한글 시스템 글꼴의 웹 작업실로 통일한다. 토스에서 영감을 받은 독립 UI이며 로고·브랜드 자산은 복제하지 않는다.
- Phase 1은 실제 영역과 HTML 편집·미리보기를 좌우 배치한다. Phase 2는 장바구니와 Hook 안내를 배치한다. 작은 화면에서는 세로로 전환한다.
- 두 화면 하단에 최근 성공한 커밋의 변경 목록과 이전·다음 VNode 트리를 표시한다. 작업을 선택하면 실제 화면의 대응 요소 위치를 외부 오버레이로 강조한다.
- 추가 폰트·패키지·CDN 없이 실행한다. 버튼 포커스, 모바일 폭, 다크 장바구니, 모션 감소 설정을 고려한다.

## 구조와 선택

엔진과 시각화의 직접 import 대신 선택적 `onCommit({plan, root, tree})` 콜백을 사용한다. UI 실행부가 관찰 모듈을 연결한다. 초기 mount에는 plan이 null이고 tree는 초기 VNode다. 이후에는 DOM과 State/History 확정 후 호출한다. 관찰 콜백 오류로 이미 성공한 커밋을 실패 처리하지 않는다.

Patch 실패 후 복구는 별도 `onRecovery({root,tree})`로 알린다. `inspector.resync`가 강조를 지우고 재생성된 DOM 참조를 다음 비교 기준으로 수집한다. 이전 성공 수치·트리는 유지하되 예전 작업 선택을 중지하고 복구 상태를 표시한다. 복구까지 실패하면 root/tree를 null로 알려 관찰을 비우고 새로고침을 안내한다. 복구 알림 예외도 원래 복구 결과를 바꾸지 않는다.

```mermaid
flowchart LR
  I[입력·State] --> D[Diff]
  D --> P[Patch]
  P --> C[State·History 확정]
  C --> O[선택적 onCommit]
  O --> V[목록·트리·외부 오버레이]
```

관찰 모듈은 초기/이전 커밋의 실제 DOM 참조를 보관하고, 다음 DOM 참조와 비교해 **재사용된 요소 수**를 구한다. Diff 작업 수를 DOM API 호출 수나 성능 측정으로 표현하지 않는다. 이벤트 갱신은 화면 작업과 별도 집계하며 필터로 확인한다. 삭제된 요소는 이전 트리에만 남고 실제 화면 강조 대상이 없다.

대안: 관리 DOM에 class/data 속성을 붙이면 기존 검증과 충돌한다. 대신 관리 루트 밖의 고정 오버레이를 쓴다. 전체 재렌더와 성능 비교는 범위 밖이다. 긴 트리·작업 목록은 표시 한도를 안내하되 집계는 전체를 기준으로 한다. 복구된 실패는 성공 기록으로 남기지 않는다.

## 구현·검증 순서

1. 관찰 모듈과 콜백 연결의 실패 테스트를 작성하고 실제 브라우저에서 RED를 확인한다.
2. `src/inspector.js`·`inspector.css`를 구현한다. 엔진은 선택 콜백만 제공하고 `app.js`·`cart.js`가 연결한다.
3. 공통 `ui.css`와 두 페이지 CSS·HTML을 개선한다. 관리 루트의 허용 문법과 기존 DOM ID는 유지한다.
4. 신규 브라우저 테스트, 기존 순수·브라우저 회귀, 데스크톱·좁은 화면 직접 조작을 확인한다.
5. README·검증 계획에 실제 결과를 기록한다. 이 작업에서는 커밋·푸시하지 않는다.
