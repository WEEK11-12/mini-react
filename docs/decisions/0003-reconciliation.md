# ADR-0003: 순수 트리 비교와 위치 기반 자식 대응

- 상태: AI 제안. 팀 미채택·미구현.
- 기록일: 2026-11-06.
- 관련: P-01~P-02, FR-01~FR-05, NFR-01~NFR-03, C-01~C-05.

## 문제

목표 화면을 만들면서 무관한 DOM 객체를 유지해야 합니다. 이전·다음 자식 중 무엇을 같은 노드로 볼지, 변경을 어떤 순서로 적용할지 명시해야 합니다.

## 대안

| 대안 | 이점 | 비용·한계 |
| --- | --- | --- |
| 전체 교체 | 단순한 구현 | 부분 갱신 요구와 정체성 보존에 부적합 |
| 위치·종류 기반 비교 | 이해·단위 검증이 쉬움, 기본 케이스 분리 가능 | 앞쪽 삽입·재정렬 시 논리 항목의 identity를 보장하지 않음 |
| key 기반 비교 | 목록 항목의 이동과 identity 표현 | key 유일성·탐색·이동·인덱스 변경 처리 추가 |
| 일반 트리 편집 최적화 | 다른 최적성 기준 탐색 가능 | 교육용 범위보다 복잡할 수 있고 비용·목적 정의 필요 |

## 제안

구조 트리를 불변 데이터로 취급하고, 순수 Diff가 명시적인 Patch 목록을 생성하게 합니다. 기본 자식 대응은 위치·종류·태그 기준으로 제한합니다. C-04의 순서를 adapter가 그대로 적용합니다.

전역 최소 변경은 보장하지 않습니다. key 기반 재정렬은 실제 필요와 검증 범위가 생기면 별도 ADR로 확장합니다.

## 이유와 결과

- 계산·DOM 변경을 분리하면 Diff를 실제 브라우저 없이 검증하고 변경 과정을 관찰하기 쉽습니다.
- Patch 목록·이전 트리를 보관하는 메모리 비용과 경로 검증 책임이 생깁니다.
- 부모 종류 교체 뒤 자식 Patch를 적용하지 않고, 자식 삭제 순서를 뒤에서 앞으로 유지해야 합니다.
- 같은 위치의 input은 유지할 수 있지만 목록 재정렬에서 논리 항목별 input 상태가 따라간다고 보장하지 않습니다.
- 이것은 우리 알고리즘 제안입니다. React가 동일한 Patch 목록이나 알고리즘을 사용한다는 근거가 아닙니다.

## 채택 전 검증 설계

동일 트리·텍스트·속성 제거·종류 교체·연속 삭제·앞쪽 삽입·중첩 변경·root 교체를 검사합니다. 결과 동등성 외에 무관한 DOM 객체 유지, 입력 트리 불변성, 실제 적용 순서도 검증합니다.

목록 항목의 포커스·내부 상태를 재정렬 후에도 보존해야 한다면 이 제안을 재검토합니다.
