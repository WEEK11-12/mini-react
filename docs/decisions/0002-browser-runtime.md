# ADR-0002: Python 실행 위치와 브라우저 연결

- 상태: 미결정. 아래 실험안은 AI 제안.
- 기록일: 2026-11-06.
- 관련: O-01~O-02, O-08, FR-02~FR-11, NFR-03~NFR-07.

## 문제

핵심 로직의 언어는 Python이지만 최종 결과는 브라우저 DOM이어야 합니다. 어디에서 Python을 실행하고 DOM·이벤트를 어떻게 연결할지 결정해야 합니다.

## 후보

| 후보 | 이점 | 비용·실패 지점 |
| --- | --- | --- |
| 브라우저 내 Python 실행 환경 | 별도 앱 상태 서버 없이 로컬 이벤트·DOM 연결 가능 | 실행 환경 로딩, Python/JS 값 변환, callback proxy 정리 |
| Python 프로세스 + 얇은 브라우저 JavaScript | 일반 Python 테스트 도구 사용이 쉬움 | 통신 순서·직렬화·세션·오래된 응답·프로세스 실행 |
| JavaScript/TypeScript로 전환 | 브라우저 API 직접 사용, 원본 조건 부합 | 현재 팀 언어 선택 변경과 학습 비용 |

브라우저 내 실행이 필요한 경계 수를 줄일 가능성은 있지만, 실험 없이 더 단순하거나 빠르다고 확정하지 않습니다. [Python 공식 안내](https://docs.python.org/3/library/intro.html#webassembly-platforms)는 Pyodide 등의 DOM 접근 경로를 설명합니다.

## 최소 실험의 입력·출력

실험은 제품 구현이 아니라 선택 근거 수집용입니다. 의존성을 설치하거나 채택했다는 의미는 아닙니다.

1. 요소·텍스트·input이 있는 작은 DOM을 읽어 Python 트리로 옮깁니다.
2. Python callback으로 버튼 클릭을 받고 숫자 텍스트만 바꿉니다.
3. input의 DOM 객체가 유지되는지 확인합니다.
4. listener를 교체한 뒤 클릭 한 번에 최신 callback이 한 번 실행되는지 봅니다.
5. unmount 후 listener·proxy를 정리하고 추가 callback이 없는지 확인합니다.
6. Python 예외·commit 실패가 사용자와 호출자에게 어떻게 보이는지 확인합니다.
7. 로딩·실행 조건과 사용한 버전·명령·실제 결과를 기록합니다.

## 채택 기준

- 위 동작을 재현할 수 있고 오류·성공 완료를 구분할 수 있음.
- 핵심 Diff·Hook 비교를 DOM 없이 테스트할 수 있음.
- UI 프레임워크에 핵심 구현을 위임하지 않음.
- 설치·배포·브리지 코드가 학습 범위에 맞음.
- O-01과 추가 실행 도구의 허용 범위를 충족함.

## 채택 후 확정할 계약

브라우저·Python·런타임 버전, 설치·시작·테스트 명령, adapter 실제 API, 비동기 commit 완료, 이벤트 proxy 소유권·해제, 분리 프로세스라면 요청 순서·세션 정책을 확정합니다.

현재 실험 결과·벤치마크는 없습니다. 버전이 표시된 공식 웹 페이지를 프로젝트의 설치 버전으로 기록하지 않습니다.
