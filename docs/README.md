# 설계 문서 지도

이 문서는 미니 UI 라이브러리를 처음 설계하는 사람과 구현 AI의 공통 진입점입니다. **문제 → 요구사항 → 구조 → 계약 → 결정 → 검증**의 흐름으로 읽습니다.

## 현재 상태와 문서의 효력

작성 기준일: 2026-11-06. 제품 코드·실행 환경·테스트 결과는 아직 없습니다.

| 표기 | 의미 |
| --- | --- |
| 확인된 사실 | 대화, 실제 저장소, 확인한 공식 자료에 근거 |
| 채택 | 사용자·팀이 선택한 방향. 구현·검증 완료를 뜻하지 않음 |
| 설계 초안 | AI가 제안한 구체적 기준. 팀 채택 전에는 확정된 구현 계약이 아님 |
| 미확정 | 확인·결정이 필요. 이에 의존하는 구현은 결정 후 진행 |
| 검증됨 | 실제 실행 절차와 결과가 기록된 항목만 해당 |

Python 선택은 팀 결정입니다. 새 API·알고리즘·런타임 제안은 별도 표기가 없으면 설계 초안입니다. 실제 React의 공개 동작과 우리 구현의 선택도 구분합니다.

## 2. 독자별 읽는 경로

- 처음 읽는 사람: 문제 정의 → 요구사항 → 아키텍처 → 필요한 API → 관련 ADR → 테스트.
- 구현자·AI: 루트 지침 → 이 지도 → 해당 요구사항 → 관련 API·ADR·테스트 → 실제 코드.
- 리뷰어·포트폴리오 독자: 루트 README → 설계 결정 → 검증 근거 → 실제 변경·기여 기록.

모든 문서를 매번 프롬프트에 붙이지 않습니다. 작업에 필요한 파일·ID를 연결하고 관련 부분을 읽습니다.

## 3. 문서 간 연결과 변경 규칙

~~~text
문제 P-* → 기능 FR-* / 품질 NFR-*
                  ↕
          API 계약 C-* ← 설계 결정 ADR-*
                  ↓
             검증 V-* → 실행 기록·커밋

과제 P1-* / P2-* / Q-* → 대응표로 FR-*와 연결
~~~

- ID는 재사용하지 않습니다. 기존 과제 ID는 대응표에 보존합니다.
- 요구사항은 결과, 아키텍처는 책임, API는 호출 규칙, ADR은 이유를 소유합니다.
- 상위 사용자 지시와 확인된 외부 제약을 우선합니다. 요구사항·API·ADR이 충돌하면 명시적으로 함께 수정합니다.
- 새 동작은 관련 요구사항·계약 변경으로 먼저 표현합니다. 문서 제목만으로 모순을 숨기지 않습니다.
- 구현 상태는 실제 코드와 최신 실행 근거로 확인합니다.
- 비밀 키·토큰·개인정보를 기록하지 않습니다.

## 4. 다음 결정

| 항목 | 현재 상태 | 다음 근거 | 위치 |
| --- | --- | --- | --- |
| Python 허용 | 미확인 | 과제 담당자의 확인 또는 예외 근거 | O-01 |
| Python 실행 구조 | 미정 | DOM 읽기·클릭·부분 변경·정리 최소 실험 | ADR-0002 |
| 자식 대응·정체성 | 위치 기반 초안 | 재정렬 한계와 테스트 확인 후 채택 | ADR-0003 |
| Hook·비교·수명 | 초안 | 계약 검토·팀 결정 | C-07~C-11 |
| 편집 UI·지원 범위 | 초안 또는 미정 | 편집 방식·지원 표 채택 | O-03~O-04, C-01~C-03 |

독립적인 문서 검토·개념 실험은 계속할 수 있습니다. 제품 구현 계획은 관련 런타임·계약을 채택한 뒤 작성합니다.
