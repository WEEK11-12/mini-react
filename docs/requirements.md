# 프로젝트 요구사항
## 1. 목적과 범위
### 1.1 목적

Virtual DOM, Diff, Patch와 함수형 컴포넌트, State, Hook을 직접 구현하여 사용자 입력에 따라 필요한 DOM 부분만 갱신하는 Mini-React를 개발한다.

구현한 기능은 브라우저에서 동작하는 실습·검증용 웹페이지와 테스트로 확인한다.

### 1.2 개발 대상

| 대상 | 역할 | 포함 범위 |
| --- | --- | --- |
| Mini-React 라이브러리 | UI 구성과 부분 갱신 기능 제공 | DOM → VDOM 변환, Diff, 초기 DOM 생성 및 Patch, 함수형 컴포넌트, useState, useEffect, useMemo |
| 실습·검증용 웹페이지 | 라이브러리 기능의 사용과 결과 확인 | 실제·테스트 영역, 편집, Patch 적용, 이력 이동, 입력·클릭에 반응하는 컴포넌트 사례 |

### 1.3 단계별 범위

| 단계 | 목표 |
| --- | --- |
| Phase 1 | DOM → VDOM → Diff → Patch의 흐름과 상태 이력 이동을 구현한다. |
| Phase 2 | 함수형 컴포넌트와 Hook을 구현하고, 상태 변경에 Phase 1의 VDOM·Diff·Patch를 활용한다. |

두 단계의 검증 화면을 하나로 구성할지 분리할지는 설계에서 결정한다.

### 1.4 기본 범위와 확장

- 필수 구현 범위는 본 문서에서 확정한 기능 요구사항과 과제의 기술 제약을 따른다.
- Batching은 과제에서 지정한 선택 항목이다.
- 컴포넌트 제거 기능은 현재 EFF-04의 권장 범위이며, 제공 방식은 별도 결정한다.

## 2. 용어
이 절은 프로젝트에서 사용하는 의미를 정의한다.

| 용어 | 정의 |
| --- | --- |
| DOM | 브라우저 문서의 구조와 내용을 나타내는 노드 트리와 조작 API |
| VDOM | UI의 구조·속성·텍스트 등을 메모리에 표현한 트리 |
| Diff | 이전 VDOM과 새 VDOM을 비교해 변경 사항을 찾는 작업 |
| Patch | 일반적으로 변경 사항을 실제 DOM에 적용하는 작업. 본 문서의 PATCH 분류에는 초기 DOM 생성도 포함한다. |
| 실제 영역 | 초기 샘플과 Patch 적용 결과를 표시하는 영역 |
| 테스트 영역 | 실제 영역에서 만든 초기 VDOM을 표시하고, 사용자가 변경 내용을 편집하는 영역 |
| 적용 기준 VDOM | 현재 실제 영역에 대응하며 다음 Diff의 비교 기준으로 사용하는 VDOM |
| State History | 적용된 VDOM 상태와 현재 이력 위치를 관리하는 기록 |
| Component | 입력과 상태를 바탕으로 UI를 구성하는 단위. 본 과제에서는 함수형으로 구현한다. |
| 루트 컴포넌트 | 컴포넌트 트리의 최상위 컴포넌트. 본 과제에서 State와 Hook을 사용하는 위치 |
| Props | 부모가 자식 컴포넌트에 전달하는 입력값 |
| State | 컴포넌트의 실행 사이에 보존되며, 변경 시 UI 갱신을 요청하는 데이터 |
| Hook | 함수형 컴포넌트에서 상태 보존·작업 실행·계산 결과 재사용 등을 제공하는 함수 |
| 의존성 배열 | Effect 재실행 또는 Memo 재계산 여부를 판단하기 위해 비교하는 값들의 목록 |
| 설정 함수 | useEffect에 전달하여 실행할 작업을 정의하는 함수 |
| 정리 함수 | 설정 함수가 반환하며, 이전 작업을 종료하거나 해제하는 함수 |
| 마운트 | 컴포넌트를 처음 실행해 UI를 표시하는 과정 |
| 업데이트 | 현재 상태와 입력으로 컴포넌트의 UI를 다시 계산하고 반영하는 과정 |
| 컴포넌트 제거 | 관리 중인 컴포넌트를 UI에서 제거하고 관련 자원을 정리하는 동작 |
