# 라이브러리 요구사항

상태: 구현 전 초안. 외부에서 관찰할 동작을 정의합니다. 방법은 [아키텍처](architecture.md), 호출 규칙은 [API 계약](api-contracts.md), 과제 조건은 [외부 제약](assignment-constraints.md)에서 다룹니다.

## 1. 범위와 시나리오

1. 앱 작성자가 UI 함수를 작성하고 루트를 mount합니다.
2. 사용자의 클릭·입력으로 상태가 바뀝니다.
3. 라이브러리는 다음 UI를 계산하고 필요한 DOM 변경을 적용합니다.
4. State·Effect·Memo는 명시한 수명과 의존성 규칙을 따릅니다.
5. 별도 편집 데모에서 DOM 읽기·Diff·Patch·스냅샷 이력을 관찰합니다.

API 초안 채택 시 아래 세부 동작도 함께 확정합니다. 모든 기능은 현재 미구현·미검증입니다.

## 3. 품질 요구사항

| ID | 요구사항 | 확인 방법 |
| --- | --- | --- |
| NFR-01 | 정확성과 결정성 | 동일 트리·정책에서 동일 Diff. 무작위 ID·시각에 의존하지 않음 |
| NFR-02 | 불필요한 DOM 교체 방지 | 무관한 객체 유지, 실제 DOM이 목표 구조·속성·property와 이미 같으면 쓰기 0회. 사용자 입력에 의한 제어 property 차이는 동기화하며 이벤트 등록 갱신은 별도 계측 |
| NFR-03 | 테스트 가능한 경계 | 트리·Diff·의존성 비교를 DOM 없이 검증 |
| NFR-04 | 명시적 입력·오류 처리 | 미지원 입력을 조용히 누락하지 않고 실패·복구 경로 노출 |
| NFR-05 | 자원 수명 관리 | 이벤트·Effect·브리지 참조의 정리 확인 |
| NFR-06 | 재현 가능한 실행 | 확인된 버전·설치·데모·테스트 명령 기록 |
| NFR-07 | 편집 입력 안전성 | 임의 코드·인라인 이벤트를 실행하지 않고 검증 오류 표시 |
| NFR-08 | 접근 가능한 UI | 키보드 조작, 컨트롤 이름, 경계 버튼·오류 상태 표시 |
| NFR-09 | 추적 가능성 | 요구사항 → 계약 → 결정 → 테스트 → 코드 연결 |
| NFR-10 | 근거 있는 성능 설명 | 트리·브리지·DOM 비용 구분, 측정 없는 성능 우위 주장 금지 |

## 4. 불변조건

- INV-01: 정상 commit 뒤 committed_tree는 관리 DOM의 지원 범위 표현과 일치합니다.
- INV-02: Diff는 입력을 바꾸거나 DOM을 읽고 쓰지 않습니다.
- INV-03: 각 History 스냅샷은 후속 편집과 독립적입니다.
- INV-04: Hook 슬롯은 루트 수명에 속하고 렌더 간 호출 순서로 대응합니다.
- INV-05: 렌더 도중 DOM 쓰기·Effect 실행·상태 setter 호출을 하지 않습니다.
- INV-06: 성공한 commit 뒤 Effect를 실행하며 실패한 후보 트리의 Effect는 실행하지 않습니다.
- INV-07: 관리 DOM과 데모 조작 UI의 소유권은 겹치지 않습니다.

실패한 commit의 완전 롤백은 현재 보장하지 않습니다. 정상 경로와 실패 경로는 C-05에서 분리합니다.

## 5. 보장하지 않는 것

임의 HTML·SVG·Shadow DOM·모든 폼 요소, 전역 최적 Diff·키 기반 이동·자동 batching·React API 호환은 현재 범위가 아닙니다. 외부 코드가 관리 DOM을 임의 변경한 경우 자동 복구도 보장하지 않습니다.

## 6. 상태와 변경

FR-01~FR-13, NFR-01~NFR-10은 모두 미구현·미검증입니다. 구현 후 항목별 상태에 관련 커밋·테스트를 연결합니다.

완료에는 해당 단위 테스트, DOM 의존 기능의 실제 브라우저 검증, 실행 안내와 알려진 제한이 필요합니다. 동작 변경 시 관련 C-*·ADR·V-*도 함께 검토합니다.
